## Установка и запуск
1. Склонировать репозиторий:
   ```bash
   git clone <ссылка-на-репозиторий>
   ```
2. Перейти в папку проекта:
   ```bash
   cd native
   ```
3. Открыть `index.html` в браузере.

Примечания:

- Шрифт Inter подключается с Google Fonts, поэтому при первой загрузке нужен интернет. Без него сработает запасной шрифт Arial.
- Для проверки сохранения данных откройте DevTools - вкладка **Application** - **Local Storage**.

## Ответы на вопросы

### Доступность формы для людей с ограниченными возможностями
- **Язык страницы.** На `<html>` указан `lang="ru"`, чтобы скринридер выбирал правильное произношение.
- **Семантическая структура.** Вместо набора `div` использованы `header`, `main`, `footer`, `nav`, `section` и `form`. Пользователи скринридеров могут переходить по этим областям напрямую.
- **Подписи полей.** Каждое поле связано с `<label>` через пару `for` / `id`. Подписи скрыты визуально классом `.visually-hidden` (элемент уводится из потока, но остаётся в дереве доступности), потому что `placeholder` не заменяет настоящую подпись: он пропадает при вводе и не всегда озвучивается.
- **Обязательные поля.** Помечены атрибутом `required`, продублированным `aria-required="true"`.
- **Сообщения для пользователя.** Блок `#form-message` имеет `aria-live="polite"`: когда JavaScript записывает в него текст («Неверный email или пароль», «Вход выполнен!»), скринридер зачитывает его автоматически, не перебивая текущее чтение. Ошибка передаётся текстом, а не только цветом.
- **Работа с клавиатуры.** Используются нативные `button`, `input`, `a`, поэтому Tab, Enter и Space работают без дополнительного кода. У полей, ссылок подвала и логотипа есть заметные состояния фокуса (`:focus`, `:focus-visible`): у полей убрана стандартная рамка, но вместо неё добавлены цветная граница и кольцо `box-shadow`, так что фокус не пропадает.
- **Декоративные изображения.** Иконки соцсетей и контактов имеют `alt=""`, так как рядом есть видимый текст, и скринридер их пропускает. У логотипа есть `alt`, а ссылка-логотип имеет `aria-label="На главную"`.
- **Бегущая строка.** Повторяющиеся копии текста скрыты от скринридера через `aria-hidden="true"`, а один экземпляр лежит в `.visually-hidden`: фраза зачитывается один раз, а не восемь.
- **Уважение настроек системы.** Для `prefers-reduced-motion: reduce` анимация бегущей строки отключается.
- **Навигация подвала.** `<nav>` имеет `aria-label="Контакты"`, а секция соцсетей связана со своим заголовком через `aria-labelledby`.
- **Автозаполнение.** Атрибуты `autocomplete="email"` и `autocomplete="current-password"` помогают менеджерам паролей и браузеру, а это снижает нагрузку на людей с моторными и когнитивными особенностями.

### Обоснование выбора подхода к вёрстке
Основной подход к вёрстке - Flexbox.

- **Раскладка одномерная на каждом уровне.** Страница это вертикальная колонка «шапка - контент - подвал». Карточка это вертикальная колонка блоков. Строки внутри (иконка + текст на кнопке, ссылки подвала) расположены горизонтально. Flexbox предназначен именно для одномерных раскладок.
- **Центрирование и заполнение высоты.** Нужно было поставить карточку по центру и по горизонтали, и по вертикали, чтобы `main` занимал всё свободное место между шапкой и подвалом. Для этого достаточно `flex: 1` у `main` внутри flex-колонки `body` и пары `justify-content` / `align-items`.
- **Иконка и текст в одной строке.** Кнопки соцсетей и ссылки подвала выравниваются через `align-items: center` и `gap`, без ручных отступов и `vertical-align`.
- **Почему не Grid?** Grid нужен для двумерных сеток (галереи, дашборды), где важны и строки, и столбцы одновременно. Здесь такой сетки нет, поэтому Grid был бы избыточным.
- **Почему не block?** В обычном потоке для центрирования и выравнивания элементов в ряд пришлось бы использовать `float`, `margin: auto` и ручные расчёты высоты, что хрупче и длиннее.

### Обоснование выбора брейкпоинтов
Использовано два брейкпоинта.

- **480px** (смартфоны). На такой ширине карточка с `max-width: 300px` и внутренним отступом 30px становится тесной, поэтому она растягивается на всю ширину (`width: 100%`, `max-width: none`), отступы уменьшаются до 20px, логотип уменьшается до 40px, а подвал перестраивается в колонку.
- **768px** (планшеты и небольшие экраны). Выше этой границы карточка фиксированной ширины выглядит нормально и правок не требует. На этом пороге уменьшается расстояние между ссылками в подвале, чтобы они не выглядели разреженными.

Значения выбраны по типичным границам классов устройств (телефон / планшет / компьютер), а не под один конкретный экран. Подход «сначала всё работает, затем правим там, где ломается»: карточка уже гибкая (`width: 50%` с ограничением по `max-width`), поэтому большое число breakpoints не требуется. Для работы media queries в `<head>` добавлен тег `viewport`.

### Обоснование способа хранения данных
Для пары логин-пароль выбран `localStorage`.

Почему?

- Функция «Запомнить пароль?» подразумевает, что данные должны пережить закрытие браузера. `sessionStorage` очищается при закрытии вкладки, поэтому для этой задачи не подходит.
- Кукисы отправляются на сервер с каждым запросом, а у проекта нет бэкенда, так что эта особенность только создаёт лишний трафик и риски. К тому же у них маленький лимит и неудобный API.
- `IndexedDB` слишком громоздкий для двух строк.
- Данные хранятся в виде JSON-строки (`JSON.stringify` / `JSON.parse`), потому что `localStorage` принимает только строки. Чтение обёрнуто в `try/catch`: пользователь может вручную испортить значение, и повреждённый JSON не должен ломать страницу.
- Сохранение происходит **только после успешного входа** и только при отмеченном чекбоксе. Если чекбокс снят, сохранённая пара удаляется.

**Важное!!** Всё, что читает JavaScript страницы, может прочитать и какой-нибудь вредоносный скрипт. Это относится и к `localStorage`, и к `sessionStorage`, и к обычным куки. Поэтому хранение пароля в открытом виде здесь сделано **исключительно в учебных целях**.

В реальном проекте пароль на клиенте не хранят вообще. Функцию «запомнить меня» реализуют так: сервер выдаёт токен сессии в cookie с флагами `HttpOnly`, `Secure` и `SameSite`, недоступной для JavaScript, а запоминание пароля берут на себя менеджеры паролей браузера (для чего в форме есть атрибуты `autocomplete`).

### Какие функции понравились
В проекте использованы оба вида.

**Именованные функции** (`function isValidEmail() {}`): `isValidEmail`, `isValidPassword`, `showMessage`, `saveData`, `loadData`, `clearData`.

- Имя работает как документация: по вызову `isValidEmail(value)` понятно, что происходит, без чтения тела.
- Это самостоятельная логика, которую можно переиспользовать и проверять отдельно.
- Они поднимаются (hoisting), поэтому порядок объявления в файле не критичен.
- В стеке ошибок отображается имя функции, что упрощает отладку.

**Стрелочные функции** (`() => {}`): обработчики `blur`, `submit`, функция `restoreForm`.

- Для коротких колбэков, которые используются один раз и привязаны к конкретным элементам формы, они компактнее и читаются прямо в месте использования.
- Не создают собственный `this`, что избавляет от неожиданностей, если колбэк использует внешний контекст.

**Что понравилось больше:** именованные функции для логики (проверки, работа с хранилищем) и стрелочные для обработчиков событий. Такое разделение делает код понятным: «что делает» вынесено в функции с говорящими именами, а «когда запускается» видно в `addEventListener`.


## Как работает жаваскрипт

1. При загрузке страницы `restoreForm()` проверяет `localStorage`: если там есть сохранённая пара, поля заполняются, а чекбокс отмечается.
2. Когда пользователь уходит с поля email или пароля (`blur`), значение проверяется регулярным выражением. Поле получает класс `valid` (зелёная граница) или `invalid` (красная граница и анимация тряски). Для повторного запуска анимации класс снимается и добавляется заново через `requestAnimationFrame`.
3. При отправке формы (`submit`) вызывается `event.preventDefault()`, затем:
   - если формат email или пароля неверный, показывается сообщение об этом;
   - если формат верный, но данные не совпадают с эталонными, показывается «Неверный email или пароль»;
   - если данные верные, показывается «Вход выполнен!», а пара сохраняется в `localStorage` (чекбокс отмечен) или удаляется из него (чекбокс снят).

Правила валидации:

- **Email:** `что-то@что-то.что-то`, без пробелов.
- **Пароль:** минимум 8 символов, минимум одна буква (латиница или кириллица) и одна цифра.
